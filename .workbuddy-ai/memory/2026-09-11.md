## 10. ROOT CAUSE of the deployed 500 — OpenIddict development certificate

The user finally pasted the developer exception page from `/swagger/index.html`:

```
CryptographicException: Access is denied.
  System.Security.Cryptography.X509Certificates.StorePal.FromSystemStore(...)
  System.Security.Cryptography.X509Certificates.X509Store.Open(OpenFlags flags)
  OpenIddictServerBuilder.<AddDevelopmentEncryptionCertificate>b__0(...)
  OpenIddict.Validation.ServerIntegration.OpenIddictValidationServerIntegrationConfiguration.Configure(...)
  OpenIddict.Validation.AspNetCore.OpenIddictValidationAspNetCoreHandler.HandleRequestAsync()
  Microsoft.AspNetCore.Authentication.AuthenticationMiddleware.Invoke(...)
```

- ABP registers a **development** encryption+signing certificate by default. That code path calls
  `X509Store.Open(...)`, which needs a Windows user profile. The IIS app pool identity has none.
- It throws from `AuthenticationMiddleware`, which runs on **every** request → 500 everywhere,
  `/swagger/index.html` included. Never reproduces locally (the dev account can open the store).
- Nothing in first-party `.cs` referenced it — it comes from ABP/OpenIddict defaults, so the fix has
  to be an explicit `PreConfigure` override.
- Earlier guesses (connection string / split-horizon DNS) were **wrong**; the Hangfire heartbeat had
  already proved the app was up with a working DB. Keeping the internal hostname anyway is correct.

### Fix applied (Host/ERPPlatform.HttpApi.Host/ERPPlatformHttpApiHostModule.cs)

In `PreConfigureServices`, only when **not** `IsDevelopment()`:
1. `PreConfigure<AbpOpenIddictAspNetCoreOptions>(o => o.AddDevelopmentEncryptionAndSigningCertificate = false)`
   (type is in namespace `Volo.Abp.OpenIddict`; package `Volo.Abp.OpenIddict.AspNetCore`, present
   transitively via `Volo.Abp.Account.Web.OpenIddict`).
2. `PreConfigure<OpenIddictServerBuilder>` → `AddEncryptionCertificate(cert)` + `AddSigningCertificate(cert)`.
3. `LoadOpenIddictCertificate()` reads base64 from `OpenIddict:CertificatePfxBase64` first, else
   `openiddict.pfx` from the content root. Loaded with
   **`X509KeyStorageFlags.MachineKeySet | EphemeralKeySet`** (keeps the key out of any user profile).
4. Because the host is **http-only** (`App:SelfUrl = http://erpplatform.runasp.net`; https returns
   000/TLS refused), also call `serverBuilder.UseAspNetCore().DisableTransportSecurityRequirement()`
   — otherwise `/connect/token` answers `invalid_request: "This server only accepts HTTPS requests."`
   (ID2083). Gated on `App:SelfUrl` starting with `http://`, so enabling HTTPS restores it.

- Base64 embedded in `appsettings.Production.json` (gitignored) rather than relying on the loose
  `.pfx`, because shared hosting can block or misplace files in the content root.
- Certificate generated with PowerShell `New-SelfSignedCertificate -KeyAlgorithm RSA -KeyLength 2048
  -KeySpec KeyExchange -KeyExportPolicy Exportable` + `Export-PfxCertificate`, 20 years,
  thumbprint `CBD88920C2DDA2942465395951F0E26C48B0982E`, pass phrase in
  `OpenIddict:CertificatePassPhrase`. `*.pfx` was already gitignored.
- csproj: `<None Update="openiddict.pfx">` with `CopyToPublishDirectory=PreserveNewest` — **not**
  `Content Include`, which would raise NETSDK1022 (duplicate item; the Web SDK already globs it).
