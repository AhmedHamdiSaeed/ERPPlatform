## ROOT CAUSE of the recurring "stuck / SQL connection" failures
The app was **never using LocalDB** in this environment, despite `Host/.../appsettings.json`
saying `Server=(LocalDb)\MSSQLLocalDB`. Both **`appsettings.secrets.json`** files override
`ConnectionStrings:Default` to an **unreachable remote DB**:
- `Host/ERPPlatform.HttpApi.Host/appsettings.secrets.json` → `db66804.databaseasp.net`
- `Shared/ERPPlatform.DbMigrator/appsettings.secrets.json` → `db66804.public.databaseasp.net`
(same creds `db66804` / `mZ=98yX@!F5e`). That's why every request threw
"Named Pipes 40 / network name no longer available / network path not found" and why the
DbMigrator seeded against a dead server. **Fix:** pointed both secrets files at LocalDB
(`Server=(LocalDb)\MSSQLLocalDB;Database=ERPPlatform;Trusted_Connection=True;TrustServerCertificate=True`)
so local dev uses the local DB. (Keep the remote strings noted in case prod needs them.)

## LocalDB behavior
- Auto-**stops** when the last connection closes → next request gets "server not found".
  Start it with `sqllocaldb start MSSQLLocalDB`; keep the host running to stay alive.
  `sqlcmd -S "(LocalDB)\MSSQLLocalDB" -E` works; pipe hash changes on every restart
  (so a stale pooled connection = Win32 64 "no longer available").
- DbMigrator + Host both read `appsettings.secrets.json`; if it points remote, migrations
  never reach LocalDB and the DB stays empty → "Invalid object name" (Error 208) at runtime.

## ABP gotcha: do NOT enable EF connection retry
`options.UseSqlServer(sql => sql.EnableRetryOnFailure())` in
`Shared/ERPPlatform.EntityFrameworkCore/.../ERPPlatformEntityFrameworkCoreModule.cs` breaks
ABP: `SqlServerRetryingExecutionStrategy does not support user-initiated transactions`
(seed/UoW transactions fail). Reverted. Fix transient LocalDB drops via LocalDB uptime, not retry.

## Module gap analysis: Payroll vs Inventory depth → `NEXT_MODULE_ANALYSIS.md`
Verdict: **Payroll second, Inventory depth third** (invert if customers are traders/distributors).
- **Payroll is additive.** Inputs already captured: `Employee.Salary`, `Attendance.WorkingHours`,
  `Attendance.OvertimeHours` (captured but never read by payroll), `Employee.LeaveBalance`,
  real `LeavePolicy` accrual engine. `PayrollAppService.ProcessPayrollRunAsync` is a stub:
  flat 15% deduction, never writes a `Payslip`. Missing: components, rules, periods, loans,
  benefits, taxes/SI, bank files, ESS, GL mapping, approval states, locking.
  Sprint 1: SalaryComponent + SalaryStructure + real payslip generation + **preview/simulation**
  + **anomaly detection** (every anomaly rule is computable from existing data) + approval chain.
- **Inventory is a foundation rebuild.** Quantity model = `Product.Stock` (single `int`) with
  `Product.WarehouseName` as a **string**. **No `StockMovement`/ledger entity exists anywhere** and
  **no cost field at all** (`Product.Price` is selling price) → valuation impossible.
  Foundation sprint: `StockLevel` (product×warehouse×bin: on-hand/reserved/available/incoming),
  `StockMovement` ledger (every receipt/issue/transfer/adjustment/variance writes one),
  `Product.CostPrice` + weighted-average valuation. Then locations, batch/expiry+FEFO,
  counting w/ freeze+variance approval, replenishment, dashboard.
- Manufacturing / Projects / Assets = frontend stubs, **zero backend** (only DTO entries in
  `Modules/HR/Application/HRApplicationAutoMapperProfile.cs`).
