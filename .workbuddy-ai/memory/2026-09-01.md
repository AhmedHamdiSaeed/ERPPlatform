A previous pass claimed "3 frontend routes return 404: crm deal-stage, goods-receipt, plan features".

### Gotchas learned
- ABP strips the HTTP-verb prefix and lowercases: `UpdateStageAsync` → `/stage`, `GetActiveProvidersAsync` → `/active-providers`. But a param can land in the **path** if the service declares it as such — always read Swagger, don't assume query binding.
- `dotnet run --no-build` after `dotnet build -o <tempdir>` runs **stale** binaries from `bin/`. Either build without `-o`, or let `dotnet run` build.
- A stale host can hold port 44327 and serve an old Swagger doc — always kill it (find PID via `netstat -ano | grep 44327`) before re-verifying.
- `dotnet-ef` needs `Microsoft.EntityFrameworkCore.Design` in the startup project; the Host lacks it. Use the `Shared/ERPPlatform.DbMigrator` project instead.
- `wmic.exe` is blacklisted by the sandbox.
- In ABP 9 the hook is `CreateFilteredQueryAsync`, not `CreateFilteredQuery`.

## Chat feature: fixed frontend ↔ backend API wiring (group chat + extras)

The chat backend (ChatConversationAppService, ChatMessageAppService, IChatNotifier +
SignalRChatNotifier, ChatHub) and the UI (team-chat.component.ts/html, chat-api.service.ts,
chat-signalr.service.ts) were already scaffolded in a prior session; the gap was that the
frontend `chat-api.service.ts` sent ids/keys as **query/body** params while ABP 9.3 exposes
them as **path** params. Verified against live Swagger (host running on :44327) and rewrote the
service so every call matches.

### Key routing facts (ABP 9.3 conventional controllers)
- Simple params become **path** segments: `available-users/{conversationId}`,
  `start-direct/{otherUserId}`, `history/{conversationId}`, `attachment/{messageId}`,
  `mark-read/{conversationId}`, `search/{conversationId}`, `toggle-reaction/{messageId}`,
  `{id}/edit-message`, `{id}/message`, `{id}/participants`, `{id}/members`, `{id}/leave`,
  `{id}/member/{userId}`, `{id}/mute`, `{id}/group`.
- Verb inference: `Create/Add`→POST, `Update`→PUT, `Remove`→DELETE, `Get`→GET, but
  **`Edit`→POST** (not PUT). `EditMessageAsync` is exposed as `POST /chat-message/{id}/edit-message`.
- The Application project (`ERPPlatform.Application`) does **NOT** reference `Microsoft.AspNetCore.Mvc`,
  so `[FromQuery]`/`[FromRoute]` attributes can't be added there. Keep backend binding as ABP defaults
  and fix the frontend instead. (Build fails with CS0234 if you add `using Microsoft.AspNetCore.Mvc`.)
- For the "create new group" user picker there is no conversation id yet, but
  `available-users/{conversationId}` requires it as a path param. Added a dedicated
  `GetAvailableUsersForNewGroupAsync` → `GET /chat-conversation/available-users-for-new-group`
  (excludes only the caller). Frontend `getAvailableUsers(conversationId, filter)` branches on null.
