## Empty-filter validation bug in chat user pickers (FIXED)
- `GetAvailableUsersForNewGroupAsync` / `GetAvailableUsersAsync` declared `string filter` (non-nullable).
  ABP auto-validation treats it as `[Required]`, so the frontend's `getAvailableUsers(..., '', 20)`
  (empty filter on first picker open) returned HTTP 400 "filter field is required".
- Fix: changed both signatures to `string? filter = ""`. Method body already handled empty term
  (returns all users). Rebuilt + restarted host; verified empty `filter=` now returns HTTP 200
  with all 4 demo users + admin.
- NOTE: `ERPPlatform_App` is a PUBLIC OpenIddict client — do NOT send `client_secret` in token
  requests (curl test with client_secret got 401 invalid_client ID2053; dropping it returned 200).
  The Angular `auth.service.login()` is correct (no secret). When testing via curl, omit client_secret.
